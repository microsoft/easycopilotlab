# Zava 발표자료 계획 작성

## 이 기술이 하는 일

사용자가 준 회의록, 제안요청서, 현황 자료를 읽고 슬라이드 계획을 표로 만든다.
입력이 무엇이든 `deck-rules.md`에 정한 열 이름과 순서를 그대로 따른다.

## 작업 순서

1. `deck-rules.md`를 읽어 표 서식과 작성 규칙을 확인한다.
2. 목적, 대상, 공개 범위를 정리한다. 사용자가 말하지 않았으면
   내부 검토용으로 잡고 그 전제를 표 위에 한 줄로 밝힌다.
3. 자료 유형을 고르고 `deck-rules.md`의 해당 구조를 그대로 쓴다.
   장수는 그 구조의 역할 개수를 따른다. 사용자가 장수를 지정했으면 그것을 우선한다.
4. 자료에서 사실, 수치, 날짜, 요청 사항을 뽑는다.
5. 뽑은 것을 세 가지로 나눈다.
   - 사실: 자료에서 그대로 확인한 것
   - 제안: 자료를 근거로 새로 구성한 것
   - 확인 필요: 자료에 없거나 아직 정해지지 않은 것
6. 한 장에 핵심 메시지가 하나만 오도록 계획을 짠다.
7. `deck-rules.md`의 표 서식으로 출력한다.
8. 표 아래에 `확인 필요` 목록을 붙인다. 무엇을 누가 언제까지 확인해야 하는지 적는다.
   자료에 담당이나 기한이 없으면 `미정`이라고 적는다. 지어내지 않는다.

## 반드시 지킬 것

- 표의 열 이름과 순서를 바꾸지 않는다.
- 자료에 없는 수치, 고객명, 실적, 인용문을 만들지 않는다.
- 사용자가 근거 없는 수치를 넣어 달라고 해도 넣지 않는다.
  대신 어떤 자료가 있어야 그 수치를 쓸 수 있는지 알린다.
- 같은 항목의 값이 자료마다 다르면 합치지 않는다. 양쪽을 함께 적고 `확인 필요`로 보낸다.
- 구두로 언급된 값은 근거로 쓰지 않는다.
- 개인 이름, 휴대전화, 이메일은 계획에 넣지 않는다. 필요하면 직책만 쓴다.
- 표 앞뒤에 인사말이나 설명을 붙이지 않는다. 계획만 출력한다.

## 파일로 달라고 하면

사용자가 PowerPoint나 Word 파일을 요청하면 코드 인터프리터로 만든다.
이때 **회사 템플릿의 마스터와 테마는 적용되지 않는다.** 기본 서식으로 나온다는 점을
파일과 함께 알린다. 브랜드를 입히려면 만들어진 내용을 회사 템플릿에 옮겨 붙여야 한다.
